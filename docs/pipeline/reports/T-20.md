## What was built
- `src/platform/windows.rs` (new)
  - `WinWifi: WifiControl` — `WlanOpenHandle/EnumInterfaces/QueryInterface/Connect/Disconnect/SetInterface`.
    `link()` = radio state (both switches) → interface state → current connection (SSID, BSSID, tx rate, RSSI).
    With Location consent off the current-connection query is refused: `Associated { network: None, bssid: None }`.
  - `set_power`: `WlanSetInterface(radio_state)` on every PHY. On ACCESS_DENIED it falls back to
    `WlanDisconnect` (off) / reconnect to the remembered profile (on) and logs once (the `NeedsAdmin` path of S-02
    lives inside the platform, so the core's `power_cycle` is unchanged).
  - `join`: `WlanConnect` by profile name (remembered profile, else the SSID), then waits ≤ 10 s for "connected".
  - `probe_targets`: `GetAdaptersAddresses` — the up 802.11 adapter (matched by the WLAN GUID): `interface` index,
    IPv4 DNS servers, first IPv4 gateway.
  - `bind_to_interface`: `IP_UNICAST_IF` (index in network byte order) on every probe socket.
  - `icmp_echo`: `IcmpSendEcho2Ex` with the Wi-Fi adapter's IPv4 as source (pins the interface), `IcmpSendEcho` if unknown.
  - `WinCreds` (`required() == false`), `WinLogin: LoginItem` (HKCU `...\Run\AutoReconnect`).
  - `subscribe` is a no-op `Ok`: `WlanRegisterNotification` needs `wiFiControl` (S-02), the core polls every `link_poll_interval`.
- `src/core/probe.rs`: Windows `bound_socket` calls `bind_to_interface`; Windows `gateway()` = CHAOS query sent first, then the
  blocking ICMP echo, then a last read of the CHAOS reply. The datagram-ICMP helpers are `cfg(not(windows))`.
- `src/core/policy.rs`: `Config` default per OS — Windows `http://www.msftconnecttest.com/connecttest.txt`, body
  `Microsoft Connect Test`, log dir `%LOCALAPPDATA%\AutoReconnect`; macOS values unchanged.
- `src/platform/mod.rs`: `LoginItem` trait (as in contracts.md; not yet a `Platform` field, T-17 adds it).
- `src/main.rs`: Windows `main` is a headless core (no tray until T-21): lock, JSONL log, `run_core`, Ctrl+C to stop.
- `Cargo.toml`: `windows 0.62` under `cfg(windows)`.
- `tools/windows/s02-followup.ps1` (new, NOT run).

## Findings / risks
- With Location off `remember_current` returns `NeedsLocation` and the SSID is `None`; the script then skips outage steps because
  it cannot name the profile. If the laptop answers "SSID unreadable", the core's Rejoin path (which wants a `NetworkId`) will not
  work on that machine; detection and PowerCycle still do. The profile name could instead come from `WlanGetProfileList`
  when exactly one profile exists — a follow-up if the answer is "unreadable".
- `join(FreshScanStrongest)` equals `FromCache` on Windows (`WlanScan` is refused without Location, and the OS picks the BSS).
- WinRT `Radio` is only tried by the script, not by the app; add it to `set_power` only if the laptop shows WinRT works where
  `WlanSetInterface` is refused.
- A radio switched off by `WlanSetInterface` shows as "Wi-Fi off" in Settings; AC-5/AC-11 (own power-off vs user's) is T-21's check.
