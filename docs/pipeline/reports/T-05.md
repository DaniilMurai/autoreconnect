## Findings
- Statistical floor: with window 6/3, the 3 s healthy cadence and 1.5–2 s probe timeouts, 11 % of runs are late even with the gateway check switched off (`lost_after_consecutive = 255`). The 3-in-a-row gateway check brings it to about 21 %: under 40 % loss a run of three comes every ~15 probes, and the gateway call (UpstreamDown/NoInternet) resets the evidence.
- Other windows on 2000 runs, % late / % restore > 10 s: 8/3 → 14 / 9; 10/3 → 11 / 33; 10/4 → 20 / 35. None reaches 0.
- Restore ≤ 10 s conflicts with staying Degraded: at 1 probe/s, 6 clean probes in a row happen during 40 % loss (0.6^6 ≈ 5 % per probe), so the state goes back to Healthy before the rule is removed.
- Model assumption: each probe is lost with p = 0.4 on its own. Real HTTP needs ≥ 2 outbound packets, so it fails more often; that speeds up detection but makes gateway flaps worse.
- What's implemented: Degraded on ≥ 3 bad in 6 when a probe got through. Leaving Degraded needs a clean window. Actions in a degraded episode are ≥ `degraded_power_cycle_after` apart, the gap is kept through NoInternet flaps, and the schedule is forgotten only after 90 s Healthy. A failure run on an already lossy link goes to the gateway only after a whole window fails. A short lost spell stays in the window as one bad probe.
