## Findings
- The own item's ACL trusts the creating build's cdhash; a new ad-hoc build asks once to read it (like Location, S-06/T-09).
- So each update to the friend costs two prompts: Location + login keychain password (no admin).
- `get` uses the default `SecItemCopyMatching`, so that prompt blocks the core loop until answered; the
  System import also blocks (S-06: 7–42 s). The import waits while health is NoInternet (AC-6).
- `credential_missing` reasons: `denied`, `not_found`, `error <OSStatus>`.

## Proposed changes
- contracts.md `CredentialStore::get`: "Never prompts" → "no prompt within one build; one login-keychain prompt after each update".
- T-13: call `Policy::set_capabilities` from the per-network credential result kept in `run` (`credentials` map).
- Release/plan: a stable signing identity would remove both per-update prompts.
