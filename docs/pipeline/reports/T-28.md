## Findings
- T-14's slow detection came from `slow_rtt` 1500 ms: under 40 % loss ~20 % of probes succeed after one TCP
  retransmit (~1 s) and were counted as good; the 6-probe clean window then sent the policy back to 3 s DNS probes.
- Leaving Degraded is the hard trade-off: under the loss ~54 % of probes are clean, so K clean in a row happens by
  chance; K must still fit AC-14's 10 s restore. Faster probes while Degraded is what makes both fit (0.54^14 ≈ 2e-4).
- Residual (~8 % in the resample test): mostly DNS + 2 HTTP timeouts in a row on a still-clean window. That is AC-2's
  outage rule (3 failures → gateway), so a run can log `connectivity_lost`/restore during the loss; not fixable without
  slowing AC-2.
- Cost: while Degraded, ~2 HTTP probes/s to captive.apple.com. A full block on an already lossy link now needs 10
  failures (~15 s) before `connectivity_lost` (was 6); AC-2 on a clean link is unchanged (live 7.9 s).
- `common.sh` writes to `runs/macos-$(date +%F)` by default, which mixes a second session's runs into the first one's
  folder on the same day; this run used `AR_RUNS=…/macos-2026-11-06-t28`.
