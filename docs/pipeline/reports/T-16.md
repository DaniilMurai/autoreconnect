## Findings
- tray-icon 0.26 on macOS hands its menu to `NSStatusItem` only inside a real mouse-down (`setMenu` → `performClick` → `setMenu(None)`). Accessibility "click" opened the menu once, then never again in run 2. Real clicks work (user check above); Accessibility clicks do not, so scripted menu checks cannot replace the user. The menu is now one `Menu` refilled in place (`fill_menu`), not replaced by `set_menu`.
- `UiModel` has no field for "credential missing" or "log unavailable", and `run_core` only `eprintln!`s a write error. Without touching `run.rs`, `main` wraps the sink in `TapSink`: it watches `credential_missing` / `credential_imported` events and write results and sends `Notice`s through the same `EventLoopProxy`.
- Location: the 60 s wait now runs inside the tao loop (`ControlFlow::WaitUntil`, 250 ms polls); the tray is up and shows "Waiting for the Location answer…" meanwhile, and the core starts on the answer or at 60 s. A later answer only updates the menu: a later grant works by itself (the SSID is read live), a later deny logs no `permission_missing` (needs a core hook, below).
- Quit sends `UiCommand::Quit` and joins the core thread before exiting, so a power-cycle in progress ends with Wi-Fi on.
- The Windows build compiles `ui::tray` (tao/tray-icon support Windows); not checked locally (no rustup), CI is the check.
